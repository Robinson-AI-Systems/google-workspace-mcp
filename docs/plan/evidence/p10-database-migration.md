# P10-B additive database migration and rollback boundary

`src/db.js:initSchema()` creates all existing tables and then invokes `src/principals/store.js:initPrincipalSchema(q)`. The new schema is V2 additive; existing `oauth_codes`, `oauth_tokens`, `google_accounts.tokens`, `google_accounts.tokens_enc`, `rtc_passes`, saved secrets, owner permissions and encrypted-only retirement flag are not rewritten, re-keyed or deleted.

New tables: `principals` (one explicit constant legacy-owner UUID, other UUID user), `principal_google_identities` (unique verified issuer/sub), `principal_google_accounts` (unique issuer/sub, composite unique id/principal owner), `principal_defaults` (composite FK to owned account), `principal_legacy_accounts` (exact existing owner email mapping only), `user_sessions` (hashed secrets and CSRF), `user_oauth_transactions` (hashed state/nonce/browser, encrypted PKCE verifier, one-use consume), `principal_oauth_codes` (one-use hashed code/PKCE/resource), `principal_connections` (hashed bearer/refresh, family/version, exact owner, composite account FK), `principal_refresh_uses` (spent refresh families), `principal_delegations` (separate encrypted grant reference, initially disabled), and `principal_deletion_requests` (recoverable request record, never irreversible deletion).

Identity never comes from first public visitor, email suffix or request-supplied principal. A new user session is issued only after verified Google SDK OIDC identity, browser-bound single-use state, and optional subject pilot admission. Scoped queries require principal id and exact owned account. Refresh is compare-and-swap for encrypted Google grants, and atomic one-time rotation for V2 MCP refresh. V2 encryption uses the existing `TOKEN_ENCRYPTION_KEY`, with AES-256-GCM AAD containing purpose, principal and account. No plaintext fallback in V2; invalid key fails closed. Legacy old ciphertext remains unchanged.

**Rollout/rollback:** Deploy source with `PUBLIC_SIGNIN_MODE=off`. Additive schema stays when rolling back code; never revert to a plaintext-only deployment or delete the owner mapping. Existing owner/Hub tokens continue to use the old tables and exact keys. No activation of pilot/public, customer delegations, new tool dispatch or irreversible deletion is included in this migration. P10-4/5 require independent source + real Postgres proof, P10-6 real provider acceptance, and P10-7 explicit owner migration/optional retirement.

## P10 C additive isolated tenant persistence

`src/principals/tenant-store.js` adds independently owned result pages, change history, rate windows, verified delegation subjects and enforced composite `(connection_id,principal_id,account_id)` foreign keys, preserving the original owner tables. `src/principals/store.js` adds an independent `refresh_version` CAS counter for Google's ordinary OAuth token refresh; it **does not** change permission `token_version`, invalidate unrelated connections or store anything under legacy owner credentials. Cross-principal raw SQL FKs and actual two-OS-process connections are tested on disposable PostgreSQL only. Source is deploy-safe with public flags OFF; customer authorization, public pilot and actual Google writes remain separate owner gates.
